## Modern 包的可拆程度与实际负担

外层同时提供 FBX、Blend、Unity 包和贴图。FBX 二进制结构中有 32 个网格对象，分别连到独立的模型节点，另有 Furniture / Deco / Plants 三个组织节点；因此可以按物件筛选，并非只能整套作为一块几何使用。包里没有整理好的独立 Prefab，后续需在 Unity 中经 Pipeline 装配与保存。

从源 FBX 的多边形索引统计，整套约 **695,803 个三角形**。这是源几何统计，不是 Unity 导入后的顶点数、实测帧率或最终构建数据。部分物件尤其重：

植物和高密度装饰不适合作为大量复制的背景。先挑桌、沙发、灯与书等真正进入构图的部分；远景装饰继续采用自绘面片或简单模型。墙画内容本来也要自绘，使用简单画框和面片即可。

29 张 PNG 源图边长为 1,024—12,288 像素，其中四株植物分别为 8,192 / 10,240 / 12,288 / 4,096。原包元数据的最大导入尺寸均为 **2,048**，启用 mipmap，未打开 Read/Write，平台覆盖均未开启。源 PNG 体积不等于显存占用；是否维持 2K、实际压缩格式和选入后占用须在目标平台导入后确认。

30 个材质均引用 Unity 内置 Shader `fileID: 46`（Standard），其贴图 GUID 都能在本包内找到；没有发现依赖 URP/HDRP 或额外自定义 Shader 的材质引用。这降低了 Built-in 工程的初始材质适配量，仍不代表透明、光照和性能已经验证。

## Avatar 特效转入世界演出的适配

MA 安装、Avatar FX 参数、手势、骨骼代理与跟随/世界固定约束，属于原来的触发与挂载方式。世界演出应复用需要的粒子、网格、材质和动画片段，再由本片导演触发；不能将 Avatar 整套控制器视为现成 Udon 世界系统。

《立体音乐魔法》含自带音乐源；它不证明特效具备四轨分析或自动跟拍能力。正式音乐继续使用 [14 音乐设计](14-fc14-music-visual-score.md) 的 FC14 四轨和统一时基，原包音乐不叠加。粒子强度可由已知音符事件、声部包络或明确的演出事件驱动，三者在实现时分别确认。

两套原粒子的随 Transform 行为不同：音乐魔法四个系统的序列化 `moveWithTransform` 均为 0，星场八个均为 1；星场 `scalingMode` 混用 0/1。它们不能未经检查就统一挂到运动世界下。落地时明确每组粒子是在场景局部、世界还是自定义参照中模拟，并检查平移、旋转、统一缩放、暂停和重播。想要随页面穿行的粒子贴着页面参照；有意留在原处的尾迹单独编排。

大闪光、覆盖视野的半透明粒子和多层叠加需按实际画面检查填充量。原包的 `maxParticles`、发射率或 Shader Model 数字均不能直接当作本片性能预算。

## 仓库已有 Shader 的审查结果

前次记录中，四个局部效果在 [20 特效参考](20-vfx-reference.md)、两个头锁效果在 [21](21-head-camera-fx.md) 有编辑器导入、`isSupported=true` 与控制台无报错的记录。本轮没有重新验证这些记录，也没有将编辑器编译当作 VR/Quest 认证。

| 项目 | 本轮发现 | 后续处理 |
| --- | --- | --- |
| 六份手写 vertex/fragment Shader | 均未显式建立 instance/stereo 宏链，包括眼睛索引的初始化与传递 | 检查并适配目标渲染路径，特别是 Single Pass Instanced；分别验证双眼、深度采样和头锁层。这是源码风险，尚无本轮头显故障实测 |
| `OWNoiseDissolve` 进度 | 标注 −1 全显、+1 全消，实际 `wave = h + _Progress - noise` 随进度增加而增加显示 | 对齐公式与接口约定，保证端点，再接演出动画 |
| `OWNoiseDissolve` 默认值 | 白噪声默认贴图使 `noise=1.25`，进度 −1 时本体 alpha 全 0，+1 也不能保证全显 | 使用明确噪声范围与默认素材，测试端点及正反方向 |
| `OWNoiseDissolve` 菲涅尔 | 深度淡出默认关闭时 `depthFade=1`，`max(fresnel, depthFade)` 恒为 1，菲涅尔参数不影响这个 mask | 分开本体、边缘与交界淡出语义，验证各开关组合 |
| `OWNoiseDissolve` 坐标 | 三向噪声使用 worldPos；景物整体移动/旋转/缩放时纹理会相对表面滑动 | 若消融应贴着物件，增加物体或场景局部参照；固定空间场效果可保留世界坐标 |
| `OWCrtGlitch` | 采样物件自己的 `_MainTex`，没有 GrabPass | 适合局部电脑/手机/浏览器画面，按事件短促使用 |
| 两个头锁 Shader 与 `OWHeadOverlayRig` | 合计四个 Pass；面片尺寸依赖手填 FOV/aspect，尚未证明头显覆盖、镜子/其他相机呈现和性能 | 保留为短段研究；“比后处理轻”“PC/Quest 都能跑”不能仅靠当前编译记录成立 |

上述消融计算问题可由源码直接确定；立体渲染、头显覆盖和平台表现仍需运行验证。本轮只记录问题，未改写其他工作中已有的 Shader。

原包需分别判断：`Add_CenterGlow` 有显式 stereo 宏；`AnimeParticlesV1.1` 和 `DissolveSphereField` 是 surface shader，Unity 可能生成立体代码，不能仅因源文件没有宏就判定故障。原 `ScreenSpace Ubershader` 有 stereo 处理，但也包含 GrabPass、深度采样和 `target 5.0`，应作为单独评估的短时效果；不能沿用为全片常态或移动端方案。
