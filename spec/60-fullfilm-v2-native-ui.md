## 文件接口

目录 `art/export/fullfilm-v2-ui/native-overlays/`；入口 `index.html` 是 QA 预览，不放入演出。完整机器可读清单为 `data/fullfilm-v2-native-ui.json`。

各组目录提供：

- `reference-*.png`：原始参考的逐字节拷贝，来源图不动。
- `background.png`：演出版派生底图，保留窗口与静态素材；原有审核说明行已改为软件语境的行列、保存或 Internet 状态。
- `fixed.png`：同一主素材内不变的正文、作品标题或标签，透明全尺寸。
- `state-00…03.png`：完整纯演出版，直接选图即可。
- `state-XX-primary.png`、`secondary.png`：两个变化层，均透明全尺寸，与底图逐像素对齐。
- `state-XX-primary-crop.png`、`secondary-crop.png`：同一透明层的最小包围裁切块；可独立移动，位置、UV与中心 pivot 记录在每个状态的 `layers`。
- `qa-preview.png`：四态对照，含来源性质与红色变化框，只供审核。

使用完整 `state-XX.png`，或者按 `background + fixed + primary + secondary` 叠加，二者择一。同一状态不要完整图与其变化层重复叠加。透明层具有本窗口内部的背景色清除块，这是为了覆盖上一段文字；不是应改成 Additive 的光效。

矩形统一 `[x,y,width,height]`，原点在图像左上。`uv_rect` 统一 `[u,v,width,height]`，原点在贴图左下，已转换 Y。不要将顶部原点的像素 Y 直接当作 Unity UV V。

`text_slots` 提供正文、气泡、译文、时间值、文件名、速率、回复计数、按钮和结果文字的矩形、像素字号、颜色与四态值。若主代理另用文字网格覆盖，先清理对应原像素文字，避免重影。所有字体按原像素尺寸栅格化，图像放大保持比例；窗口、工具栏、按钮和面板不要各自拉伸。

## 六组的来源边界

1. **README**：`data/episode123-art.json` 中 `readme` 原创记事本，是本片示例工具箱文档。Win98 Explorer 作为另存的真实 VM 参考，不冒充 README 的拍摄证据。
2. **漫画**：`episode123-v4-score.json` 的 `workflow-manga-2` 与既有原创漫画流程。漫画本身、台词和人员都是原创示例，不归于真实作品或汉化组。保留原页、原气泡和原图层位置。
3. **字幕**：Aegisub 官方文档配图来源与版本路径原样复用现有 metadata。助手标题栏、按钮、快捷键及原尺寸保留，只有示例原文、译文与当前行号替换。右侧时间轴是既有原创 operation，与真实助手分成两个完整窗口，不伪称同一张历史实截；其新增波形选区、入出点和字幕句均为原创复原。
4. **BT**：真实图内标题是 **BitComet 0.53**，既有图库页面标题为0.63的矛盾保留于 metadata，不能改称0.63。原图截图日未核；数字和文件名已改为本片原创《我们的短片.mkv》，128 MB、8 MB每块、16块、6块=37.5%，并同步更新标题栏与实际列下速率，不能当作真实下载。UI状态只表达区块、校验与继续分享，不提供下载地址。
5. **论坛**：保留天涯原首页的全局导航、搜索、左导航、底栏与原窗口尺寸。原图另存；中央主题与 `xxxx` 回复是无特定事件的原创互助演示，没有真实账号、新闻断言或真实帖子归属。来源网页捕获时间和源画面内容的固有差异不在这轮擅自改写。新增回复与发表控件不声称来自原首页。
6. **访问条件**：沿用既有原创 `access_conditions`，地址仍为 `service.example`。它只表达通用登录、兼容与范围，不点名真实公司、事件或限制通知；原三个按钮轮廓和位置保留。

全部来源记录直接复用现有 metadata，包括源标题、版本、日期限制、分类与 SHA-256。新增状态的统一性质是 `original-dynamic-reconstruction`。演出贴图不烧入“原创动态复原”“不是历史实截”等审核文字；这些说明仅在本文件、JSON、QA图和演后统一署名中出现。文件名、版本、行列、保存状态等符合软件语境的内容可以出现在窗口内。
