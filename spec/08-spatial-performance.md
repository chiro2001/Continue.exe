# 08 三维 VR 空间演出

## 已确认的创作方向（2026-10-15）

用户要求充分使用 3D VR 的空间特性：大量内容的堆叠、仅点亮远方局部、突然出现与尺度变化、短暂改变观演位置与所处环境，以及暂时隔离玩家之间的视觉和听觉。上述能力参与情节和情绪设计。

用户进一步提出以包围视野的摄像机画面，或达到同样效果的其他方式，固定观众看到的方向，形成无法回避的直视、压迫感和张力。此类视觉呈现不能仅因主相机位姿接口只读而排除，具体单眼或立体方案仍需验证。

2026-10-16 用户进一步提出保持人物参照，整体移动、缩放与旋转其他场景，使原地观众像乘观光车一样进入三维内容。当前建议将这一原生几何路线作为连续进入、穿行与尺度变化的主方案，详见 [20](20-world-motion-performance.md)。真实玩家维持原生追踪，NPC 独立表演，稳定支撑与接触道具另行分组；摄像机画面覆盖保留为特定短段备选，不默认执行。

玩家的距离感、身体尺度、注意力方向及同伴是否在场，都可以成为叙事变量。Kipfel / Nemesis 是首批演员外观，人物数量可以增加，精细动作后续通过用户动捕替换。

用户后续提出 FC14 四分轨空间音乐，声音的位置、距离和接力同时参与上述演出；详见 [spec/14](14-fc14-music-visual-score.md)。环境/视点切换需同时组织听觉落点；玩家语音与 Avatar 音频的暂时隔离不自动等于将本世界音乐静音。

主音乐最新约束是常态前方融合、四声部轻微可辨，高潮才短暂明显分拆；视觉和环境声仍可充分展开三维空间。主音乐不因每次场景变化都转为全周环绕。

主要内容的美术来源已明确为自绘图形与排版、分层面片、简单模型和现有资产复用，详见 [17](17-art-production-plan.md)。常规页面和工位保持世界中的朝向，实际层间距离、遮挡、背面和实体边框提供空间观察；少量朝向观众的装饰与短暂视野替代分别处理。

同一页面中的插画或场景继续按前景、主体、中景与背景分别绘制和摆放；场景组统一构图，内部层次以真实距离提供双眼视差与侧移遮挡。补齐被遮住的区域，近处可绕看的部分按需要加简单体块；正文与控件保留紧密、可读的排版关系。

用户进一步要求至少一长段没有空间边界，另有一段超越空间界限。当前方案见 [19](19-spatial-scene-plan.md)：无界段撤去包住整体的房间与场地边沿；再兴段候选用小窗容纳大场景、内外互换和远近重构改变空间关系。原场地坐标降为局部支撑与排练参考，具体时窗与技法待验证；接口和双眼/恢复边界继续适用。

具体人物关系、叙事视点、下述桥段与演出时长仍是讨论稿。本轮仅更新规格与核对官方文档，没有操作 Unity 或实现视听隔离原型。

## 推荐的情绪结构（讨论稿）

先建立真实的共同空间，让观众感到其他人就在身边；中段逐层撤去连接，最深处短暂进入各自的空间；最后让声音、人物与通路逐步重新出现。

| 候选段落 | 空间表现 | 对情节的作用 |
| --- | --- | --- |
| 第一次回应 | 黑暗里只亮一个小房间；另一处窗口回应它，房间由近及远出现 | 看见一次分享如何抵达陌生人 |
| 共享扩展 | 房间在前后左右与上方展开，人物各做各的事，文件从身边传过；近处保留一个可读的关键动作 | 让社区具有规模和生活痕迹，转头也能发现内容 |
| 入口受限 | 手边小窗口长成建筑；进度条延伸为长廊，弹窗与关口侵入共同空间，观众之间的视线逐渐受阻 | 等待与阻隔成为身体能感到的距离 |
| 维护者 | 用短暂遮黑切换观演落点，来到工作桌一侧；请求从四周抵达，远方的大量依赖仍在运转 | 让观众靠近承担工作的人；精细停顿留给后续动捕 |
| 信任破裂与失联 | 演员的复制品突然增多、变大，原作者的名字脱落；随后内容密度骤降，各观众只剩局部灯光与一个失效入口 | 副本的繁荣与人的退场并置；让失联被实际体验到 |
| 重新连接 | 先出现确定的键盘声、设备启动声或人物动静；一盏新灯亮起，再恢复同伴的声音与共同空间 | 用少量恢复建立希望，远处仍保留未亮的房间 |

短暂个人段落建议集中在第二幕低点，聚集与分离因此有足够分量。具体时长待音乐与空间原型验证后确定。

## 表达原则

- 密度与留白共同组织节奏。密集段让每次转头都能发现内容；关键动作通过局部光、运动和声音保持清楚。
- 先用桌椅、人物和手边物件建立身体尺度，再让物件长成建筑或让玩家进入原本遥远的局部，尺度变化才有参照。
- 声音可以先于视觉引导注意力。关键叙事音使用预制素材保证可发生，真人语音增加现场感，不作为推进剧情的必要触发条件。
- 突然出现、放大和转场尽量落在音乐事件上。连续进入和穿行优先试制共享演出曲线驱动的世界运动；局部落点切换仍可用短遮黑与传送。人物与稳定支撑不随布景整体变换，接触道具按状态交接。
- 常规段落保留自然的头部追踪反馈；关键短段可尝试固定或替换视觉呈现，使转头不再改变所见构图。头显与系统仍在追踪真实姿态，作品控制的是所呈现的画面。离开演出或演出结束时恢复自然视野、共同观演位置及本世界管理的视听设置。

## VRChat 能力核对

2026-10-15 查阅官方文档所得，仍需在本工程与实际客户端中做原型验证：

| 目标 | 已核实的能力与限制 |
| --- | --- |
| 改变观演位置与进入另一环境 | `TeleportTo` 可以改变本地玩家的位置和朝向；各客户端分别执行，共享演出时间基准。移动观演站点可使用 `VRCStation` |
| 直接改写头显主相机位姿 | `VRCCameraSettings.ScreenCamera.Position` 与 `Rotation` 为只读；这限制直接接口，不排除用摄像机画面覆盖视野或补偿场景运动来控制视觉呈现 |
| 固定或替换观众所见画面 | 已找到 Camera + RenderTexture + 屏幕空间 Shader 的公开实现；目标画面不必沿用实际头部的观看方向。示例存在不代表已在本工程验证 VR 双眼、完整视野覆盖与稳定性 |
| 暂时听不见其他玩家 | 本地可把其他玩家的 `SetVoiceDistanceFar` 调为 0；Avatar 自带音频还需单独处理 `SetAvatarAudioFarRadius`。将语音增益设为 0 dB 不等于静音 |
| 暂时看不见其他玩家 | 优先采用不同观演落点、隔开的空间及本地场景内容。相机的 CullingMask 有保留层限制，不以可以任意隐藏玩家 Avatar 为前提 |

## 视野固定与立体呈现（候选技法）

本节当前为特定短段的备选研究，不是世界运动主路线的前置条件。世界运动随演出时间驱动；本节部分补偿方法随头部位姿驱动，两者的目标和状态管理分别设计。

核心是让指定画面相对用户视野保持固定。采用包围几何时，需要视线跟随或采样补偿；采用屏幕空间 Shader 时可直接按屏幕坐标呈现。固定在世界里的普通全景内容仍允许转头查看不同方向，本身不等于锁定构图。

| 路线 | 可用的表达 | 需要验证的部分 |
| --- | --- | --- |
| 单眼摄像机画面覆盖视野 | 把玩家短暂关进一张旧界面或 CRT 画面；平面感可以参与情节 | 同一张图给两眼不具有所拍场景的双眼视差；应明确作为平面呈现设计 |
| 分眼渲染并合成 | 固定构图同时保留目标场景的立体深度 | 左右眼图像分别生成和正确采样，处理眼间距、每眼投影和画面匹配；支持单通道立体渲染的 Shader 本身不会把单眼图像变成立体图像 |
| 本地显示场景补偿头部运动 | 候选：让专用视觉场景随观众位姿补偿运动，用原生双眼渲染保持立体关系 | 作为推导出的原型路线，尚未实现；视觉层与实际站立/碰撞层分开，核对转动、平移、姿态更新时序与延迟 |

创作上建议在“入口封闭”或“信任破裂”中短暂使用：玩家转头寻找同伴，关闭的窗口仍占据视野中心；结尾解除固定，窗口落回空间中的一个物件，玩家能再次转头看见共同空间与其他人。该桥段尚未定稿。

固定视觉反馈会产生真实头部运动与所见运动不一致的感受，压迫感与不适都可能增强。首个原型采用短段、稳定构图，验证后再决定运动强度和时长。验收包含桌面与 VR 双眼、近物深度、转头/点头/侧倾、头部平移、进入退出的连续性及多人独立呈现；Unity 单相机截图不能代替头显验证。

已阅读的公开参考（仅研究，未导入第三方资产）：

- [ganlvtech / VRChat ScreenSpaceCameraRenderTexture](https://github.com/ganlvtech/vrchat-screen-space-camera-render-texture)：README 明确给出 Camera + RenderTexture + 屏幕空间 Shader 路线。
- [LiveDimensions / VRC ScreenSpace CameraOverride](https://github.com/LiveDimensions/VRC-ScreenSpace-CameraOverride)：README 描述球体内覆盖 RenderTexture，并提及 VR 时的桌面串流相机用法；不能据此认定它已正确实现头显立体替代。
- [Unity 2022.3：Single-pass instanced rendering and custom shaders](https://docs.unity3d.com/2022.3/Documentation/Manual/SinglePassInstancing.html)：每眼索引与立体纹理采样的官方说明。

## 后续实现接口

- 全局演出时钟决定剧情阶段；本地观演控制器决定当前落点、可见场景、观演站点和声音阶段。
- NPC 演员与真实观众分别管理。演员的复制、消失与放大是场景内容；观众的分离和重聚是本地观演状态。
- 集中管理本世界对其他玩家语音和 Avatar 音频应用的参数，进入个人段落、加入实例、退出演出与重播时都走相同的恢复逻辑；避免多个脚本相互覆盖。
- 复归时检查位置、朝向、站点退出、玩家间视听及本地遮黑状态。单人、多人和中途加入均需验证。
- 内容规模按画面需要设计，再用可见范围、分区、远景和演员细节等级落实性能预算；不把所有观众看不到的内容同时完整更新。
