# 17 美术制作：自绘内容、空间面片、简单模型与资产复用

状态：2026-10-15。用户明确以自行绘制的大量平面内容作为画面丰富度的主要来源，放入三维空间的面片，配合简单建模与现有资产复用。本稿据此组织制作方案；数量、样张和具体模型为首轮估算，尚未生产或导入。剧情与已选片尾沿用 [15 全片串联稿](15-integrated-show-outline.md)，现有资源位置以 [16 素材盘点](16-asset-inventory.md) 为准。机器可读计划见 [data/art-production-plan.json](../data/art-production-plan.json)。

用户进一步明确：同一块面片所表达的场景内部，也分开绘制前景、主体、中景与背景，以适量的实际前后距离增强立体感。制作时同时规划场景之间和单幅画面内部两级深度。

当前采用按年代还原旧内容、轻度调色协调、前期屏幕/窗口承载而后期逐渐自由展开的方向，见 [18 风格规格](18-visual-style-direction.md)。前轮同构图对照只作构图与氛围留档，其简化界面不作为年代还原标准，也不计入 124 个生产母素材成品。

这些素材在三维场地中的位置与跨段复用见 [19 场景规划](19-spatial-scene-plan.md)。正常大小器物提供操作与尺度，多人必读内容可通过保留机身或版本边框的放大载体展示；实际可读性由后续灰盒和头显检验。

空间方向进一步包含长段无界与一段内外/远近关系重构。自绘活动片段不固定围合成三间房，无界段不画包围整体的外壳与地板边沿；复制与分层布景另用于检验局部容纳整体，数量估算不因此标记为已生产。

## 制作分工

画面的辨识度主要来自我们自己的图形、排版、插画、小动画和内容组合。自绘内容放入真正有前后关系、尺度和遮挡的三维场所；人物、手边器物与少量实体结构建立身体尺度，现成房间和家具提供生活痕迹。

| 层次 | 主要制作方式 | 画面作用 |
| --- | --- | --- |
| 时代内容 | 自绘图形、界面重建、排版、原创示例与短循环 | 旧桌面、网页、论坛、字幕与汉化、发布、社区生活、错误和协作等具体文化内容 |
| 内容的空间形态 | 分层面片、轮廓裁切、简单挤出、边框与支架 | 窗口、纸页、目录、字幕图层、文件分块变成可围绕观察的物体与结构 |
| 近处实体 | 简单建模与现成小物件 | 电脑、键鼠、存储介质、工位、门框、台座建立尺度、接触和操作的可信度 |
| 环境与功能 | 从已有资产中选择并适配 | 房间、桌椅、灯、少量环境、展示框、镜子与共同画板等支撑演出 |

“平面绘制”包括矢量图形和精确排版，也包括像素画、涂鸦、原创漫画示例与材质细节。不同年代保留自己的色彩、边框、字体和布局，整体通过尺度、构图和转场连接。

## 先做可复用的素材家族

首轮容量建议为 **124 个图形/动画母素材单位，加 18 种简单模型原型**。简单模型较前版增加按键机与早期智能手机两种候选。这是分工和估量方式，不是已经完成或必须一次做齐的数量；一条循环按一个设计单位计，其逐帧绘制量另计。同一幅场景拆出的多个深度层归于同一个母素材，图层导出张数、补画与绘制工作量另记；124 个母素材不等于 124 张导出图，层数与工时估算在试制后细化。

| 家族 | 母素材单位候选 | 具体内容 |
| --- | ---: | --- |
| 界面壳与排版模板 | 10 | 桌面窗口、对话框、浏览器、论坛帖、列表、发布页、时间轴和展示板等基础组合 |
| 桌面与移动终端内容 | 8 | 开机/目录、个人主页、编辑与试用、自制作品、按键机菜单与早期智能手机页面 |
| 网页与公共生活 | 16 | 长帖、日志、相册、博客引用、早期微博、教程、留言和社区公告等重建内容 |
| 汉化、漫画与字幕工位 | 12 | 原创示例对白、译稿、清字/嵌字分层、术语表、字幕时间轴、贡献名单 |
| 发布与分发 | 8 | README、版本说明、发布帖、索引、分块、上传与接收状态 |
| VRChat 社区内容 | 8 | 旧空间导览图形、世界/Avatar 展示卡、活动海报、制作与教学面板 |
| 条件、报错与受阻 | 4 | 登录/访问条件、维护提示、来源缺失、无法运行等可组合内容 |
| 重建与合作 | 8 | 资料与代码对照、AI 辅助制作过程、具体求助、批注、共同验证和新用途 |
| 图标、贴花与小装饰 | 40 | 文件/状态图标、按钮、徽章、横幅、手绘箭头、贴纸、站点装饰和空间标识 |
| 短循环 | 10 | 光标、加载、分块交换、GIF 风格小动画、表情、扫描与局部响应 |

模板与内容分开。一个浏览器壳可以承载多张主页，一组图标可以进入桌面、发布帖、文件流和远景；不同内容、局部裁切、时代样式、状态和空间组合形成实际画面量。仍需为各文化家族制作有区别的内容与轮廓，避免仅换颜色就视为新的文化素材。

简单模型首批原型：CRT 显示器、机箱、键盘、鼠标、音箱、调制解调器/路由器、软盘、光盘、U 盘、文件夹体块、纸页叠、窗口边框、入口框、栏杆/关口、模块化工位、展示台座。形状以主要轮廓与少量厚度为主，界面、按键和标识细节由贴图与文字提供。

新增载体候选为按键机和早期智能手机的简单外壳，分别保留对应按键/软键提示或触屏布局。终端内容按具体系统与屏幕像素网格绘制，界面字体模式参考实际年代配置；旧机型造型由适配的复用件或简单建模提供，不因已有手机道具就认定其年代合适。两种新增模型先作为载体试制候选，不自动要求进入同一开场镜头。

## 面片如何在 VR 中形成空间

- **场景组中的确定朝向。** 大多数页面、窗口和漫画层保持所属场景组内的朝向；场景组可按 [20](20-world-motion-performance.md) 统一运动，图层不逐个追随头部。观众转头或侧移时，仍可观察前后遮挡、轮廓与厚度；小型装饰按用途处理。
- **拆层。** 一个窗口可以拆成外框、底色、内容、选区和悬浮提示；漫画拆为原稿、清字、对白与嵌字；字幕工位拆为画面、轨道与文字。层间距为实际三维距离，关键层的移动与合拢有可见结果。
- **同一幅场景内部拆景深。** 页面里的插画、漫画格或房间画面继续拆为前景、主体、中景、背景等独立绘制层，挂在同一个场景组下，沿局部深度轴拉开适量距离。面片组有统一构图，各层有真实遮挡与两眼视差。
- **给近物加结构。** 手边屏幕有机壳，纸页有背面和纸叠，入口有门框，较厚的窗口有侧边。观众能绕近看的地方使用简单实体，远处用更简化的面片和轮廓。
- **按距离安排信息。** 近处一个主要动作与必要文字，中景提供同类活动和人物，远景用招牌、轮廓、窗口与少量循环形成规模。三个层次的内容密度、对比和运动分别控制。
- **用图形组装空间。** 目录变为层层展开的架构，分块拼成通路或场所，网页边框长成门，论坛纸片形成有空隙的街面；真实几何承担通行和接触。

不把同一张单眼合成图当作三维深度的替代。面片本身可以是平面物体；其在空间中的深度由实际位置与两眼视差产生。视野替代仍是 `spec/08` 的独立短段候选，常规场面使用自然的空间观察。

### 同一幅画面内部的制作约定

以一张原创工作室/旧空间插画为例，可按远到近组织：

| 层 | 单独绘制的内容 | 空间作用 |
| --- | --- | --- |
| 远景 | 窗外天色、城市或远处灯光 | 提供画面的最远层 |
| 背景 | 墙、门窗、墙面装饰 | 建立房间范围，补齐主体后方 |
| 中景 | 桌椅、书架、设备 | 形成主体周围的遮挡关系 |
| 主体 | 插画人物或主要物件 | 提供注意力落点，可按需要独立动作 |
| 前景 | 桌角、栏杆、招牌、局部装饰 | 侧移时与中远景产生更明显的位置变化 |

具体层数随画面而定。绘制时保持统一参考构图、尺度与锚点，组装时按参考视点对齐，再从侧方与双眼检查。正文、界面控件等需要保持排版关系的元素以紧密浅层组织；画面内部的场景元素承担较明显的深度，不对每一行文字统一拉开。

被前景挡住的背景和主体仍需补画，边缘留出观演范围所需余量；不同视角露出的区域应有完整内容。各层可以裁去无用透明边，但保留原始画布定位与偏移数据，使裁切和图集不破坏对齐。近处可绕看的边缘按需要加侧面、背面或简单体块。

源文件保留命名图层、参考合成图与层间关系；按用途导出独立 PNG 或 SVG，记录父场景编号、图层编号、远近顺序、锚点/偏移及遮挡补画范围。正式层间距由构图尺寸和观演范围决定，当前不设统一厘米数。真实 NPC 继续使用骨骼演员，插画内的人物可以按画面需要拆层绘制。

首批试制应包含一个这样的分层小场景，检查正面合成、偏侧观察、补画区域、双眼深度与关键文字可读性。音乐可驱动图层逐步展开、合拢或交接；常态各层保持场景组的空间关系。

## 现有资产怎样使用

盘点依据是包内文件与路径，有些资源在其他工程使用过；当前项目中的兼容、分件粒度与表现仍按实际使用验证。以下为挑选方案，不表示整包已导入或功能已经可用。

| 候选资源 | 本片用途 | 使用取舍 |
| --- | --- | --- |
| Room01、VRS 家具包 | 一间可辨认的工作/生活空间，桌椅、灯、书和小物件提供身体尺度 | 先选一个房间或工作区和必要道具；Room01 分件能力需核对，包体积不能直接当作运行内存 |
| 城市夜景天空盒、55 Skybox pack | 夜间远景与低对比环境 | 按场面选择少量环境，保持自绘内容的主要地位 |
| Photo Clip、ArtBoard、镜子 | 展示支架与早期 Hub 的空间关系 | 优先用外观和摆放机制；镜子及 Avatar 向组件按当前世界需求适配 |
| QvPen、WorldLighting、Bakery | 演后共同涂画、可见度与制作光照 | 功能按需采用；Bakery 是编辑器工具，不作为世界内物体 |
| ISOLATION-CUBE、错误框、便签、故障粒子与全息材质 | 入口、报错、过载段的局部效果或造型参考 | 检查世界/Avatar 用途，控制局部使用范围，并统一与自绘图形的关系 |

Okaeri 营地、LakeStar 与各类趣味装置保留在盘点池，待具体场面需要再选。片尾沿用“一起做下去”的开放工作场面，旧施工单中的计数器归零、磁盘合拢等桥段不因找到现成道具而恢复。

## 七段怎样使用同一套内容

| 段落 | 自绘内容与空间组合 | 可复用关系 |
| --- | --- | --- |
| 接入 | 电脑、按键机、早期智能手机或有明确边框的浏览器承载对应年代内容，先建立屏幕尺度与边界 | 载体、窗口、作品与工位成为后续辨认点 |
| 繁荣 | 屏幕和窗口逐步展开，翻译与字幕、发布和分块、公共生活、Avatar/世界图像在前中远景出现 | 图层合拢、分块拼装、页面边框接成入口，旧样式在放大后仍保留 |
| 条件改变 | 熟悉界面增加具体条件，窗口与关口变大，工作台出现待处理事项 | 使用前段同一类版式与模型，让动作和可用条件的变化可辨认 |
| 过载 | 副本阵列、请求、来源缺失和重复宣传图形挤占空间，名字与许可逐步脱落 | 复用前段内容并改变复制、署名与回应状态；构图更加重复、压迫 |
| 骤空 | 撤去近景与大多数面片，只留远处的一个作品、文件或 README 与局部光 | 通过已见物的缺席与距离产生落差，保留足够留白 |
| 再兴 | 旧资料和新工具组成工位，具体求助接到共同演示、批注与验证；新版本和新作品出现 | 同一作品与窗口恢复响应，加入新的贡献、用法与空间连接 |
| 继续 | 工位与共同画板仍有人使用，成果交接与新点子留下可见动作，片尾上屏 | 保留旧作者与新贡献，让既有空间继续容纳后续活动 |

繁荣与过载都可以拥有大量内容：繁荣时各物有来处、人的动作有作用；过载时重复、遮挡、署名脱落与无效请求改变同一组内容的意义。骤空段主动撤去丰富层，留白本身是全片资产调度的一部分。

## 生产与交付顺序

1. **先检验四个场面样张。** 用繁荣、过载、骤空、再兴各一张空间构图，检验自绘内容、面片深度、实体与演员的关系；正式搭建时另做头显验证。
2. **做可拼装的试制套件。** 先选 10 个图形母素材：窗口壳、浏览器壳、论坛帖、汉化示例、字幕工位、BT 发布/进度、VR 展示板、贡献名单、访问/错误内容、AI 与互助工位；配 5 个简单模型原型和 Room01/VRS 的少量环境件。
3. **扩充内容家族。** 按通过检验的版式、色彩和空间语法扩展内容与短循环，逐项记录真实来源或原创示例性质。
4. **制作状态与组合。** 正常使用、传播、失去来源、无法响应、重建、新用途和新增贡献分别改变内容、层次与动作，分别统计母素材、深度层导出、动画帧与场景实例。
5. **统一导出与验证。** 绘图源、导出图、可编辑文字和用途记录一并保留。Unity 侧的材质、Prefab、导入设置和场景装配依 `UNITY-GUIDE.md` 与 Pipeline 按批次实施；截图和头显反馈用来检查层次、可读性与性能。

永久源素材建议放 `art/source/`，运行导出放 `art/export/`，目前尚未创建这些素材。矢量界面/图标优先保留 SVG，插画保留分层源文件与 PNG 导出；需要改写、翻译、逐字出现的主要文字保持可编辑，不烘成不可修改的小字贴图。

真正需要透明边缘的图形单独安排，普通页面尽量用不透明或适合裁切的面片；图集按共同使用和渲染需求分组，避免把全片都挤入一张始终驻留的大图。重复元素、远景和空间分组在正式搭建中选择合并、实例化或预置批次，不把素材张数直接当作独立材质或对象数。预算结合纹理驻留、透明重叠、材质批次、演员与实际头显测试确定，旧原型的面数上限不自动继承。

## 绘制与证据的关系

本片区分界面/空间的绘制重建、原创叙事示例与真实事实卡。重绘的旧网页和新闻排版仍标明参考年代、出处与重建性质；真实引文保留核过的原文。漫画、游戏与字幕的制作流程可以用原创演示内容表现。待核资料和未定位指控不因画成了一张图就升级为事实。

当前成果是制作方向、素材家族和复用计划；没有生成成品图片、模型或 Unity 资产。音乐四声部的前方融合与高潮短暂展开原则、群像、双线和已选片尾均保持有效。
