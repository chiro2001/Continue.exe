# 38 V4：共同旅行、历史名牌与入口条件

本轮保留 V3 两版 Hub、四位演员、换身和最后的维护归档场面，把移动改为同一个世界参照下的旅行，并让「入口还在，使用条件变了」成为能够阻拦路线的三维变化。舞台文字面向观看的人；演员头顶只显示昵称，不显示制作职责或验收标签。

实现独占文件为 `OWEpisodeV4HubCast.cs`、`OWV4HubCast.cs`、`OWV4Nameplates.cs`；V3 文件不改。场景目标为 `Assets/Scenes/OWM_Episode123_v4.unity`，新资源归入 `Assets/OldWebMap/Episode123/Revision4/`。Unity 操作仍由主代理统一执行。

## 同一个世界参照

主代理的 `OWV4Journey` 提供 `worldFrame` 与 `RegionOffset(int)`。区域分别为工作区 `(0,0,0)`、2017 Hub `(0,0,24)`、2019 Hub/Home `(0,0,52)`、条件与维护区 `(0,0,80)`。模块根 `Revision4 Hub and Cast` 挂在 `worldFrame` 下。

| 内容 | 固定的区域位置 |
| --- | --- |
| 工作区、书架和分发车 | region 0 |
| 2017 Hub | region 1 + `(0,-.045,4.1)` |
| 2019 Hub | region 2 + `(0,-.04,5.1)` |
| 2019 Home | region 2 + `(-7.8,-.04,6.2)` |
| 2017 / 2019 Avatar 与 World 选择面板 | 各自 region + `(0,3.2,6.4)`，各有一套实际对象 |
| 条件闸口 | region 3，最后按叙事退远 |
| 维护归档工位 | region 3 + `(4.65,0,4.9)` |

这些布景与面板不再各自从远处飞入，也不在每帧加上当前相机偏移。共同的 `worldFrame` 取负虚拟位置，外部窗口、环境和目标区域内容随同一参照移动。目标 Hub 在到达前已经放在对应位置，可以在接近时看见。2017 和 2019 的菜单分别留在各自空间，不能用一块始终跟观众走的面板抵消旅行。

演员以区域锚点迁移：79.36—81.92 秒 region 0→1，86.40—88.32 秒 region 1→2，102.40—104.96 秒 region 2→3。它们在锚点上继续原有走位，并与观众一同进入下一处场所。实际玩家没有传送、位移或力的操作。演员的视线目标先作为模块局部坐标，再经 `worldRoot.TransformPoint` 转为世界坐标，避免父级旅行后视线仍指向旧位置。

## 入口确实挡住了路

五层窗口框仍保留远近关系，但新增三道实际网格闸口。每道有厚重立柱、密排金属栏杆、横梁、半透明隔断、可旋转的双扇门、抬升横杆，以及独立的红叉与绿色解锁标记。实体栏杆合成持久网格，透明板只补充隔断感，不以文字代替阻拦。

| 时间 | 阻隔变化 | 人物与结果 |
| --- | --- | --- |
| 102.40—109.00 | 「选择与兼容」闸口从打开转为合拢，前方有「保留现有方法 / 切换兼容方法」两个选项 | 三位演员停在第一道闸前，不能直接走过 |
| 109.00—115.20 | 第一道红叉保持，后方「安全验证」隔断和横杆合拢 | 检查、询问和选择发生在闸前；不能只靠继续向前穿过稀疏框架 |
| 115.20—117.76 | 兼容选择后第一道打开，绿色标记出现 | 演员到 117.76 秒后才穿过第一道 |
| 118.40—120.32 | 安全验证完成，第二道打开 | 归档者先停在第二道前，120.32 秒后才通过；安全验证也提供了可用的通路 |
| 117.76—122.88 | 侧面的「辅助与维护」窄闸仍关闭，随后经调整打开 | 第四位演员等待在侧路前，122.88 秒后才进入；与主路有不同的使用需要 |
| 122.88—133.12 | 入口组向远处退去，维护台与档案架留在近处 | 演员回到检查、保存、递交和归架；128 秒保留已保存的书与回执 |

对白与标牌使用「入口还在，使用条件变了」「需要选择兼容的入口」「正在进行安全验证」「原来的方法暂时失效」「调整后，继续使用」等观看者能直接理解的句子。不出现 Agent 注释、测试说明或职责审核标签。3Q、登录/兼容、EAC 与可访问性资料的具体来源和年份由主蒙太奇承担，这组几何表现其使用条件的变化，不冒充历史客户端截图。

所有新增闸口、隔断、箭头和名牌都没有 Collider。阻拦由演员路径与门的确定时序共同完成，不用移动碰撞体推动实际观看玩家。`Validate()` 检查闸口关闭时演员停在前方、条件组 Collider 数为 0。安全、便利与可访问性各有获得回应的过程，不把全部变化演成永久封死。

## 历史名牌的依据

2017 年的语义依据来自 VRChat 于 **2017-03-06** 发布的 `PATCH 0.11.6 – What's In A Name?`。官方原文可从 [Steam News API](https://api.steampowered.com/ISteamNews/GetNewsForApp/v2/?appid=438100&count=100&maxlength=0&enddate=1489104000) 读取：当时灰色表示听不到，绿色表示能听到，金色用于 Host；耳朵、说话和好友是另外的图标。**2017-10-27** 的 0.12.0p2 又明确增加名牌文字黑描边，见 [官方旧版补丁记录](https://docs.vrchat.com/docs/patch-notes-pre-2018)。这些不是 2018 年 Trust Rank 颜色。

形态还参考了 [MoguLive 2023 年对历史回忆馆的报道](https://www.moguravr.com/vrchat-started-here/) 中明确标为「初期 VRChat 名牌」的[照片](https://assets.moguravr.com/uploads/2023/01/202301121123508000.jpg)：横向圆角长牌、阶梯式上沿、深底、白字和细描边。本轮已下载并实际查看。该照片是 2023 年展示旧物，未标每件展品的精确版本，因此它只支持早期形态，不据此把照片断定为 2017 年实拍。

2019 的参考包括 [2018-09-26 官方 Trust and Safety 调整说明](https://medium.com/@vrchat/vrchat-safety-and-trust-system-changes-and-feedback-a3a9e54ec572)：好友金色和 Trust Rank 文字属于该系统时期。世界 Udon 不据此推算真实玩家的 Trust Rank、好友关系或客户端静音状态。本版两种年代用旧式轮廓与细微的中性配色区分，真实玩家不被任意标成 Host、Friend 或某个 Trust 等级；不将 2018 的信任颜色追溯到 2017。

史料原文与图片留在 `~/tmp/vrc-old-web-map/episode123-v4/hub-cast/` 供检查。名牌是历史视觉层，不能伪装成读取了客户端未提供的权限状态。

## 演员和实际玩家

演员的自然昵称是「小满」「阿澄」「木木」「北辰」。四个名牌跟随当前实际可见身体的头骨；84.48 秒后切换身体，名牌也跟随替代 Humanoid 的头部。原先「工具制作 / 转译校对 / 分发归档 / 维护引路」头顶标签已删除。

按本轮追加意见（`spec/41-v4-focus-spacing-and-sound.md`），演员和实际玩家的可见文字统一为 `xxxx`，不读取 displayName 作为名牌内容。名牌池在编辑器中预制 **80 个槽位**，运行时不创建 GameObject；join/leave 后恢复空闲槽与匿名标签，roster 每秒检查，玩家头部每 0.125 秒更新。演员只有 4 个，跟随确定性采样更新。姓名文本关闭富文本解析，不把名字当成标记语言。

名牌的独立场景根为 `OW V4 Historical Nameplates`，不挂在 `worldFrame` 下。原因是实际玩家的身体留在物理空间，不能让头顶文字跟着历史场景平移。定位始终取实际头部世界位置，并通过父系 `InverseTransformPoint` 写回局部位置；朝向也转换回父系旋转。演员头部虽然来自移动的场景，使用同一世界位置跟随规则即可正确显示。这个根需要主代理集成时保留在物理参照中。

历史名牌只在两版 Hub 的 79.36—102.40 秒出现，其他段收起。它是附加的演出视觉层，世界不控制客户端原生名牌开关，也不冒充系统权限或信任级别。

## 保留与验证

V3 已解决的内容继续保留：从 Cast prefab 固定基准拟合约 1.25 米可见 Renderer 包围盒、落脚归零、固定 bind pose 动作基准、实际 Avatar 预览、换身只切 Renderer 而不关闭 Animator、低矮接触托板、Room01 家具三轴尺寸限制、原生双眼镜面及未初始化灰蓝纹理。四主演沿用已修正的场景材质，并复制到 Revision4；替代身体先复用同外观主演的材质，再建立本版副本，不退回原 Avatar 的强曝光材质。

公开入口：

- `OWEpisodeV4HubCast.RepairPrograms()`：绑定并编译 HubCast 与 Nameplates 两个 Udon 程序。
- `Build()`：在停止的 V4 场景中构建并标记修改，不自行切场景或保存用户其他改动。
- `Sample(float)`：采样演员、名牌和场面；共同旅行由主编排先采样 Journey。
- `Validate()`：检查各区域固定位置、共同父级、闸口与演员阻拦时序、无新增闸口碰撞体、材质副本、身高和脚底。
- `ValidateNameplates()`：80 槽满池、离开变 79、重新加入恢复 80、匿名一致性、2017→2019→收起，以及父级平移/旋转下头部世界位置误差。
- `ValidateHands()` / `InspectCastGeometry()`：继续提供实际骨架手部分离与几何检查。

验证临时改变的采样、预览槽、名牌父系与 worldFrame 位置都会在 `finally` 恢复。池化验证使用预览数据，不当作真实 80 客户端网络测试；真实玩家 join/leave、客户端双眼镜子和完整 Udon 演出仍由主代理统一验证。建议重点截图 81.92、85.12、88.64、110.08、118.80、121.60、124.16、129.28 秒，并检查目标区域的外部窗口与环境随同一次旅行移动。
